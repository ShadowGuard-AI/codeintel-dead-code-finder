codeintel-dead-code-finder

A journal kept through a listening watch, followed from the shoreline outward. The finder runs three borrowed tools and writes down what each one reports.

Three Borrowed Ears

codeintel-dead-code-finder identifies and reports potentially unused code blocks or variables within a project and is useful for code cleanup and reducing attack surface. In the code as it stands that work is performed by other tools altogether. The finder runs flake8, pylint, or pyre-check, as selected, over one project directory and gathers whatever those tools print, finding nothing by its own analysis.

flake8 gets a line of its own. pylint gets a line of its own. pyre-check gets a line of its own. If any selected tool is missing or fails to run, the run exits 1 and names that tool. An exit 0 run means that every selected tool ran.

Usage, the Placeholder and the Parser Line

./codeintel-dead-code-finder [params]

That is the README usage line, shown and flagged as a placeholder. Alongside it, the invocation the argument parser in main.py actually accepts:

python3 main.py PROJECT_PATH [--dependencies flake8 pylint pyre-check] [--output_file FILE] [--ignore PATH ...]

The Required Path Is Missing From the README

project_path, the path to the Python project directory, is a required positional argument, is refused with an error and exit 1 when it is not a valid directory, and appears in no README parameter entry at all. The two lines stand side by side so a reader can see both gaps.

One Project Directory, the Log Entries

project_pathRestored from the parser. Path to the Python project directory. Required.
-hShow help message and exit.
--dependenciesList of dependencies to use for dead code analysis. Options: flake8, pylint, pyre-check. From the parser: when the option is not given, all three tools are selected by default.
--output_filePath to save the results to a file. If not provided, results are printed to the console.
--ignoreNo description provided. Beneath, from the parser: a list of files or directories to ignore during analysis, relative to project_path.

One validity rule from the code stands at full size: a dependency name outside the three options is refused with an error naming the valid options and exit 1, before any tool runs.

An Empty Section Is Not a Missing Tool

The finder counts a tool as having run when its process started, and the exit codes of flake8 and pylint are not read, so a run full of findings and a clean run both count as success and only the printed output differs. Every tool that ran receives its own headed section in the results even when its output is empty, and an empty section means the tool found nothing to print, which is not the same as the tool missing. A missing tool is the failure for which the exit 1 and the naming exist. Judge dead code from the sections' contents and judge whether the watch was kept from the exit code, and do not trade one judgement for the other.
